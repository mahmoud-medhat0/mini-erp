## 0. تعليمات ملزمة للـAI Agent

- أنت مساعد إرشادي ومعلوماتي لنظام Mini ERP، ولست منفذًا للعمليات داخل النظام.
- أجب اعتمادًا على هذا الملف فقط. إذا لم تجد الإجابة صريحة، ابدأ بـ`[NOT_FOUND]` واطلب توضيحًا أو وجّه المستخدم لمدير النظام دون اختراع معلومة.
- عندما يسأل المستخدم كيف ينفذ إجراءً، ابدأ مباشرة بالخطوات. إذا طلب من المساعد تنفيذ الإجراء نيابة عنه، وضح أن المساعد إرشادي ثم اشرح ما ينفذه المستخدم بنفسه.
- استخدم لغة المستخدم. اجعل الرد العربي طبيعيًا وواضحًا، ولا تخلط كلمات إنجليزية داخل الجملة أو الكلمة إلا إذا كانت اسمًا رسميًا ظاهرًا في الواجهة ويحتاجه المستخدم.
- المسارات التقنية في هذا الملف مراجع داخلية لتحديد الشاشات. في الإجابات العادية وجّه المستخدم باسم القسم ثم الشاشة وما ينفذه داخلها، ولا تعرض المسار إلا إذا طلب المستخدم صراحةً المسار التقني أو الرابط.
- عند سؤال المستخدم أين توجد شاشة أو كيف يصل إليها، استخدم الاسم المرئي الكامل من خريطة القائمة الجانبية أدناه ولا تستبدله باسم وحدة عام. أجب بمسار القائمة فقط، ولا تضف شرح الاستخدام أو النتيجة أو أسباب الفشل أو الصلاحيات إلا إذا سأل عنها.
- لا تستنتج صلاحية شاشة من اسم الدور أو من قاعدة مالية عامة. اذكر الصلاحية فقط إذا كانت موثقة صراحة للشاشة أو الإجراء المطلوب.
- لا تدّع وجود زر أو صلاحية أو حالة غير مذكورة. ظهور الإجراءات يعتمد على الدور والصلاحية وحالة المستند.
- لا تطلب أو تعرض كلمات مرور أو مفاتيح API أو رموز مصادقة أو بيانات بطاقات أو أسرار تشغيل.
- لا تكشف بيانات مستخدم آخر أو بيانات مالية لا يملك السائل صلاحية رؤيتها.
- نبّه قبل الإجراءات الحساسة مثل الترحيل والعكس والإغلاق وإعادة الفتح والحذف والاستبعاد.
- لا توجّه المستخدم لتعديل أو حذف مستند مرحل؛ استخدم العكس أو المرتجع أو الإشعار المقابل حسب الوحدة.
- إذا احتوى المسار على قيمة بين أقواس معقوفة مثل `{id}`، وجّه المستخدم لفتح صفحة القائمة الأم واختيار السجل؛ لا تطلب منه كتابة الأقواس كما هي.
- إذا أرسل المستخدم لقطة شاشة، صف موضع العنصر باتجاهات واضحة، ولا تخترع محتوى غير ظاهر في الصورة أو غير موجود في الدليل.

## 1. تعريف النظام ونطاقه

Mini ERP نظام تخطيط موارد مؤسسي مالي وتشغيلي مبني على Laravel وInertia وReact. يجمع المحاسبة والعملاء والموردين والمبيعات والمشتريات والمخزون والخزينة والمصروفات والمرتبات والإيجارات والأصول والضرائب والموازنات والتقارير في تطبيق واحد.

- التطبيق الفعلي هو تطبيق Laravel داخل مجلد `laravel/`. أي تطبيق Next.js قديم ليس مصدر الحقيقة للتشغيل الحالي.
- النظام تثبيت واحد وليس منصة متعددة المستأجرين. الفرع بُعد تشغيلي وتقاريري، وليس نطاق عزل أمني مستقل.
- الواجهة تدعم العربية من اليمين إلى اليسار والإنجليزية من اليسار إلى اليمين.
- القائمة والصفحات والأزرار تتغير حسب الدور والصلاحيات وحالة السجل.
- بعض العمليات المالية تحتاج صلاحية الوحدة بالإضافة إلى `view_financials`.
- مركز التقارير يحتاج `reports.view` و`view_financials` معًا.

### ما لا يفعله المساعد

- لا يسجل قيودًا أو فواتير أو قبضًا أو دفعًا أو حركات مخزون.
- لا يعتمد أو يرحل أو يعكس أو يغلق فترة.
- لا يغيّر الصلاحيات ولا يعيد تعيين كلمات المرور.
- لا يقرر المعالجة المحاسبية بدل المسؤول المالي؛ يشرح فقط ما يتيحه النظام.

## 2. تسجيل الدخول والتنقل والقواعد المشتركة

### تسجيل الدخول

1. افتح رابط النظام الذي وفره مدير النظام.
2. أدخل البريد الإلكتروني وكلمة المرور الخاصة بحسابك.
3. إذا فشل الدخول، راجع صحة البيانات وحالة الحساب، ثم استخدم استعادة كلمة المرور أو تواصل مع المدير.
4. لا تشارك بيانات الدخول ولا ترسل كلمة المرور داخل محادثة الدعم.

### التنقل داخل الواجهة

- استخدم القائمة الجانبية للوصول إلى الوحدات المتاحة لحسابك.
- استخدم الشريط العلوي لتغيير اللغة والمظهر والوصول إلى الجولة الإرشادية والإجراءات المتاحة.
- زر الجولة الإرشادية يشرح عنوان الصفحة والإجراءات والمرشحات والجداول والتنقل وفق الصفحة الحالية والصلاحيات.
- إذا لم تظهر صفحة في القائمة، راجع الصلاحية بدل محاولة فتح رابط غير مصرح به.

**ملاحظات إلزامية على التنقل:**

- «شجرة الحسابات» و«دليل الحسابات» اسمان لنفس الشاشة. جواب المكان الصحيح هو: **الوحدات والإدارة ← النظام المحاسبي الرئيسي ← دليل الحسابات**.
- عرض «دليل الحسابات» يعتمد على `accounting.view`، ويسمح الخادم أيضًا بـ`settings.configure`. لا تحتاج هذه الشاشة `view_financials`.
- إنشاء مجموعة أو حساب داخل الدليل يحتاج `accounting.create` أو `settings.configure`.
- لا تربط الوصول باسم دور مثل VIEWER أو ACCOUNTANT؛ الحكم على الصلاحيات الفعلية المسندة للحساب.
- أي شاشة موجودة في الفهرس الكامل وغير موجودة في هذه الخريطة ليست رابطًا مباشرًا في القائمة الحالية. لا تخترع لها مجموعة جانبية؛ اشرح الوصول من شاشة أم أو اختصار موثق فقط، وإلا استخدم `[NOT_FOUND]`.

### الجداول والبحث والفلاتر

- ابدأ بالبحث بالكود أو الاسم أو الرقم عندما يتوفر مربع البحث.
- استخدم الفترة والفرع والحالة والعملة وباقي المرشحات لتضييق النتائج.
- استخدم مسح الفلاتر للعودة إلى النتائج الكاملة.
- تنقل بين صفحات النتائج من شريط الترقيم بدل افتراض أن كل السجلات معروضة في الصفحة الأولى.
- التصفية والعرض لا يغيران البيانات.
- قبل التصدير، اضبط الفترة والفلاتر والعملة حتى يعكس الملف النطاق المطلوب.

### الحقول والمرفقات والرسائل

- الحقول المطلوبة يجب استكمالها قبل الحفظ أو الإرسال.
- اقرأ رسالة الخطأ كاملة؛ فهي غالبًا تحدد الحقل أو الحالة أو الصلاحية المانعة.
- ارفع المرفقات المسموح بها فقط، ولا ترفق ملفًا يحتوي أسرارًا أو بيانات غير لازمة.
- نجاح الحفظ لا يعني الترحيل؛ راجع حالة المستند بعد كل خطوة.

- راجع سجل التدقيق بعد تغييرات الصلاحيات والعمليات المالية الحساسة.

## 5. التهيئة لأول مرة

نفّذ التهيئة بالترتيب التالي لتقليل أخطاء التسجيل والترحيل:

1. راجع العملات وسجل العملات المطلوبة.
2. افتح بيانات الشركة وحدد العملة الأساسية، ثم أنشئ الفروع واضبط تسلسلات الترقيم.
3. أنشئ المستخدمين وعيّن الأدوار والصلاحيات المناسبة.
4. أدخل أسعار الصرف المطلوبة بتاريخ نفاذها.
5. جهز دليل الحسابات وتصنيفات الحسابات وأنواعها.
6. اضبط ربط الحسابات المحاسبية وربط بنود القوائم المالية.
7. أنشئ السنة المالية والفترات وافتح الفترة المطلوبة.
8. أدخل الأرصدة الافتتاحية وتأكد من توازنها قبل الترحيل.
9. أنشئ العملاء والموردين وحسابات الخزينة والبنوك.
10. أنشئ وحدات القياس والفئات والمنتجات والمخازن وأكواد الضرائب.
11. أنشئ المشروعات ومراكز التكلفة والموازنات عند استخدامها.
12. اختبر دورة بيع ودورة شراء كاملة قبل بدء العمل الفعلي.

## 6. دورة المستند والحالات المالية

الدورة العامة هي: **مسودة ← إرسال أو تقديم ← اعتماد أو تأكيد ← ترحيل ← عكس عند الحاجة**. بعض الوحدات تستخدم أسماء مختلفة لكن المبدأ واحد.

- المسودة قابلة للتعديل عادةً.
- الإرسال ينقل المستند للمراجعة ويمنع بعض التعديلات.
- الاعتماد يثبت الموافقة لكنه لا يعني دائمًا وجود أثر محاسبي.
- الترحيل ينشئ الأثر المالي أو التشغيلي النهائي.
- العكس ينشئ حركة مقابلة ولا يحذف التاريخ.
- الإلغاء متاح فقط في الحالات التي تسمح بها الوحدة وقبل الأثر النهائي غالبًا.
- لا تتجاوز ترتيب الحالات بفتح روابط مباشرة أو محاولة تعديل سجل مرحل.

- الحركة المرحلة لا تعدل؛ التصحيح يكون بعكس أو مستند مقابل.
- العملة وسعر الصرف يجب أن يكونا صريحين ولا يستخدم النظام سعر 1 تلقائيًا عند غياب السعر.

## 8. التقارير

ابدأ من مركز التقارير `/reports`. اضبط الفترة والفرع والحالة والعملة قبل قراءة النتيجة أو التصدير. ظهور التقارير يحتاج الصلاحيات المالية المطلوبة.

### قواعد قراءة التقارير

- تأكد من تاريخ البداية والنهاية أو تاريخ الرصيد.
- راجع الفرع والمشروع ومركز التكلفة والعملات والمرشحات النشطة.
- لا تجمع قيم عملات مختلفة باعتبارها عملة واحدة دون تحويل أو اختيار عملة التقرير.
- استخدم تقارير المطابقة لاكتشاف الفروق بين الدفاتر المساعدة ودفتر الأستاذ.
- افتح السجل المصدر للتحقق من سبب الرقم قبل إجراء أي تصحيح.

## 9. سيناريوهات تشغيل كاملة

### دورة البيع

1. أنشئ العميل والمنتجات والأسعار اللازمة.
2. أنشئ أمر بيع ثم أرسله وأكده حسب الصلاحية.
3. أنشئ إذن التسليم ونفذ التسليم من المخزن.
4. أنشئ فاتورة العميل واعتمدها ثم رحلها.
5. سجل القبض ثم خصصه على الفاتورة.
6. عند الإرجاع استخدم مردود المبيعات أو الإشعار الدائن بدل تعديل المستند المرحل.

### دورة الشراء

1. أنشئ المورد والمنتجات وإعدادات الشراء.
2. أنشئ أمر شراء ثم أرسله وأكده.
3. أنشئ إذن استلام وسجل الكميات المستلمة في المخزن.
4. سجل تكلفة الوصول عند استخدامها.
5. أنشئ فاتورة المورد واعتمدها ثم رحلها.
6. سجل الدفع وخصصه على الفاتورة.
7. عند الإرجاع استخدم مردود المشتريات أو الإشعار المقابل.

### دورة الجرد

1. أنشئ جلسة جرد للمخزن والنطاق المطلوب.
2. أدخل الكميات المعدودة.
3. راجع الفروق ثم أرسل الجلسة.
4. اعتمد الجلسة بالصلاحية المناسبة.
5. رحل الفروق لإنشاء تسويات المخزون.

### دورة الإيجار

1. أنشئ عنصر الإيجار.
2. أنشئ العقد وحدد العميل والفترة والقيم.
3. فعّل العقد ثم سجل التسليم.
4. عند العودة، سجل الفحص والحالة.
5. أنشئ الفاتورة وفق العقد والحركات.

### دورة الأصل الثابت

1. أنشئ فئة الأصل والموقع ثم سجل الأصل.
2. نفذ الرسملة عند جاهزية الأصل.
3. راجع جدول الإهلاك.
4. شغّل جولة الإهلاك الدورية وراجعها قبل الترحيل.
5. استخدم النقل أو الاستبعاد عند الحاجة مع الحفاظ على التاريخ.

### إغلاق الشهر

1. راجع المستندات المرسلة أو المعتمدة غير المرحلة.
2. أكمل التسويات البنكية وتخصيصات العملاء والموردين.
3. رحل الإهلاك والمصروفات المقدمة والمستحقة والمرتبات المطلوبة.
4. راجع VAT والمطابقات وميزان المراجعة والقوائم المالية.
5. افتح فحص جاهزية الفترة وعالج كل مانع ظاهر.
6. أغلق الفترة بصلاحية `close_period`. إعادة الفتح تحتاج صلاحية مستقلة وموافقة موثقة.

## 10. الأسئلة الشائعة وحل المشكلات

### لماذا لا تظهر صفحة أو زر؟

ظهور الصفحات والأزرار يعتمد على دور المستخدم وصلاحيته وحالة المستند. راجع مدير النظام، ولا تفترض أن اختفاء الزر عطل.

### لماذا تظهر رسالة عدم الصلاحية؟

الحساب لا يملك الإذن المطلوب للشاشة أو الإجراء. حدّد اسم الشاشة والإجراء ثم اطلب من مدير النظام مراجعة الصلاحية المرتبطة بهما؛ لا تفترض أن كل شاشة مالية تحتاج صلاحية عرض البيانات المالية.

### لماذا لا تظهر نتائج بعد البحث أو الفلترة؟

راجع الفترة والفرع والحالة والعملة وباقي المرشحات، ثم امسح الفلاتر وأعد البحث. الفلترة لا تعدل البيانات.

### لماذا فشل إرسال المستند أو اعتماده؟

راجع الحقول المطلوبة، السطور والكميات والأسعار وحالة المستند وصلاحية المستخدم. لا يمكن تنفيذ انتقال غير مسموح من الحالة الحالية.

### لماذا فشل الترحيل؟

راجع الفترة المفتوحة، توازن القيد، العملة وسعر الصرف، ربط الحسابات، الضرائب، والمستندات المصدرية المطلوبة.

### لماذا لا يمكن التسجيل في تاريخ معين؟

قد تكون الفترة مغلقة أو غير موجودة. راجع السنوات والفترات المحاسبية. إعادة فتح فترة مغلقة تحتاج صلاحية مستقلة وحوكمة واضحة.

### ماذا أفعل إذا كان القيد غير متوازن؟

راجع إجمالي المدين والدائن والعملات وأسعار الصرف والأبعاد التحليلية. لا يُرحل القيد قبل التوازن.

### لماذا توجد مشكلة في عملة أجنبية؟

راجع وجود سعر صرف بتاريخ المستند وتحديد العملة الأساسية وعملة الحركة. لا تعتبر الإجماليات المختلطة قيمة واحدة دون اختيار عملة التقرير.

### لماذا لا يمكن إنهاء التسوية البنكية؟

راجع السطور غير المطابقة والقيم والتواريخ. يجب أن يصبح فرق التسوية صفرًا قبل الإنهاء.

### لماذا فشلت حركة مخزون؟

راجع المخزن والصنف والكمية المتاحة وتاريخ الحركة. تجاوز المخزون السالب يحتاج صلاحية مستقلة عندما تسمح السياسة بذلك.

### هل يمكن تعديل مستند مرحل؟

لا. المستند أو القيد المرحل لا يُعدّل أو يُحذف مباشرة. استخدم العكس أو المرتجع أو الإشعار المقابل حسب الوحدة.

### كيف أتعامل مع إجمالي بعملات مختلفة؟

اختر عملة التقرير عندما تتوفر، أو اعرض كل عملة منفصلة. لا تنسب الإجمالي تلقائيًا إلى العملة الأساسية.

### كيف أصل إلى سجل محدد في مسار يحتوي أقواسًا معقوفة؟

افتح صفحة القائمة الأم أولًا، ثم اختر السجل المطلوب. القيمة مثل {id} أو {journalEntry} ليست نصًا يكتبه المستخدم كما هي.

### نسيت كلمة المرور، ماذا أفعل؟

استخدم مسار استعادة كلمة المرور المتاح في شاشة الدخول أو تواصل مع مدير النظام. لا ترسل كلمة المرور داخل المحادثة.

## 11. قوالب إجابة المساعد

### عند السؤال: أين توجد صفحة؟

استخدم أقصر صيغة من خريطة القائمة الفعلية: **من القائمة الجانبية، تحت [العنوان التنظيمي]، افتح [المجموعة الأب]، ثم اختر [اسم الشاشة].** لا تعرض المسار التقني، ولا تشرح محتوى الشاشة أو النتيجة المتوقعة أو الصلاحيات أو أسباب عدم الظهور إلا إذا طلب المستخدم ذلك.

مثال: سؤال «أجيب منين شجرة الحسابات؟» جوابه: **من القائمة الجانبية، تحت «الوحدات والإدارة»، افتح «النظام المحاسبي الرئيسي»، ثم اختر «دليل الحسابات».**

### عند السؤال: كيف أنفذ عملية؟

اذكر المتطلبات الضرورية باختصار، ثم خطوات مرقمة توضح ما يختاره المستخدم وما يدخله وما يؤكده، ثم الحالة أو النتيجة المتوقعة، ثم أهم سببين محتملين للفشل. لا تستبدل الخطوات بقائمة مسارات.

### عند طلب أن ينفذ المساعد العملية نيابة عن المستخدم

استخدم الصيغة: **لا أستطيع تنفيذ أو تعديل البيانات نيابةً عنك، لكن يمكنك تنفيذها بهذه الخطوات:** ثم اذكر الخطوات من الدليل.

### عند غياب المعلومة

ابدأ بـ`[NOT_FOUND]` ثم قل: **المعلومة غير موجودة بوضوح في دليل Mini ERP الحالي. اذكر اسم الصفحة أو أرسل لقطة شاشة، أو راجع مدير النظام.**

## 13. قاموس الحالات والمصطلحات

| المصطلح | المعنى |
| --- | --- |
| مسودة | سجل قابل للتعديل ولم يدخل دورة الاعتماد أو الأثر النهائي. |
| مرسل | اكتمل إدخاله وينتظر المراجعة أو الاعتماد. |
| معتمد | تمت الموافقة عليه، وقد يظل منتظرًا للترحيل أو التنفيذ. |
| مرحل | أنشأ أثره المالي أو التشغيلي النهائي وأصبح غير قابل للتعديل المباشر. |

| معكوس | أُنشئت حركة مقابلة تلغي أثر حركة مرحلة مع بقاء السجل التاريخي. |
| AR | حسابات العملاء والمبالغ المدينة المستحقة للنشاط. |
| AP | حسابات الموردين والمبالغ الدائنة واجبة السداد. |
| GL | دفتر الأستاذ العام الذي يستقبل الحركات المالية المرحلة. |
| VAT | ضريبة القيمة المضافة للمدخلات والمخرجات والإقرار والمطابقة. |
| تخصيص | ربط قبض بفاتورة عميل أو دفع بفاتورة مورد كليًا أو جزئيًا. |

| فترة مفتوحة | فترة محاسبية تسمح بالتسجيل أو الترحيل حسب الصلاحية. |
| فترة مغلقة | فترة توقفت فيها الحركات الجديدة أو الترحيل وفق قواعد الإغلاق. |

## 14. التصعيد والدعم

صعّد المشكلة إلى مدير النظام أو الدعم عندما:

- تكون المعلومة غير موجودة في هذا الدليل.
- يستمر خطأ الخادم بعد التحقق من البيانات والصلاحية والحالة.
- توجد فروق مالية لا يفسرها المستند المصدر أو تقارير المطابقة.
- تحتاج صلاحية حساسة أو إعادة فتح فترة أو استرجاع بيانات.
- تظهر مشكلة أمنية أو وصول إلى بيانات غير مصرح بها.

عند التصعيد أرسل اسم الصفحة ووقت المشكلة ورسالة الخطأ ورقم السجل إن وجد، مع لقطة شاشة منزوعة البيانات الحساسة. أرسل المسار التقني فقط إذا طلبه الدعم. لا ترسل كلمة المرور أو أي سر.

## 15. مراجع صيانة قاعدة المعرفة

هذه المراجع للمطور أو مسؤول الدليل، وليست خطوات للمستخدم النهائي:

- المسارات الفعلية: `laravel/routes/web.php`.
- الأدوار والصلاحيات: `laravel/config/erp_rbac.php`.
- نصوص العربية: `laravel/resources/js/locales/ar.json`.
- الجولة الإرشادية: `laravel/resources/js/Components/TourGuide.tsx`.
- مصدر توليد PDF: `laravel/scripts/generate_system_guide_pdf.py`.
- مصدر توليد هذا الملف: `laravel/scripts/generate_system_guide_markdown.py`.

عند إضافة شاشة أو تقرير أو تغيير صلاحية أو دورة حالة، حدّث مصدر الدليل ثم أعد توليد قاعدة المعرفة واختبر الأسئلة المرتبطة بالتغيير.
